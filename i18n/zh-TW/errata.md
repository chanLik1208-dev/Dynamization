# errata.md — 範例錯誤：這包文件會誘發的錯誤

`pitfalls.md` 是給你「東西明顯壞掉、你照著症狀查」的時候用的。**這份檔案是給你「看起來完全沒壞」的
時候用的。**

底下每一則，都是某個已經讀過對應章節、而且正照著做的人犯下的錯。這正是重點：這些不是知識的失誤，而是
驗證的失誤。沒有一則會拋錯。沒有一則會印警告。大部分都上線了。

寫之前讀一遍，說「我做完了」之前再讀一遍。

---

## 怎麼用

每一則都先講**靜默症狀**，因為你能拿到的線索就只有這個。接著是錯的寫法，然後是為什麼一個有能力的實作者
還是會這樣寫，然後是修法，最後是**一個你真的跑得動的自查**。

自查才是這份文件的承重結構。一條你無法驗證的規則，就是一條你遲早會違反的規則。

---

## A. 你照著章節做了，然後被環境吃掉

### A1. 祖先節點的裁切把預渲染的陰影抵消掉了

**靜默症狀：** hover 時位置有動，但層級感永遠沒出現。在淺色主題下，`contrast.md` §2 把*所有*層次都
放在陰影裡，於是這個 hover 最後只剩下位移在撐場面 —— 這正是 `SKILL.md` §5 警告過的「半套表達」。

```css
/* ❌ */
.card { border-radius: 4px; overflow: hidden; box-shadow: var(--e2); }
.card::after { inset: 0; box-shadow: var(--e3); opacity: 0; transition: opacity .13s; }
.card:hover::after { opacity: 1; }
```

**為什麼會這樣寫：** `contrast.md` §6 叫你用交叉淡入預渲染好的陰影，而不要去動畫 `box-shadow`，這個
建議是對的。另一邊，一張圓角卡片上方放了圖片，角就得裁掉，而在卡片上加 `overflow: hidden` 是直覺反應。
兩個決定各自都沒錯。但陰影是畫在元素方框*外面*的，所以裁切會把它抹掉 —— 而且是靜默地抹掉，因為過場照跑，
只是跑在一個沒人看得到的圖層上。

```css
/* ✅ 裁該裁的東西，不要裁那個負責投影的東西 */
.card { border-radius: 4px; box-shadow: var(--e2); }          /* no overflow here */
.card .media { border-radius: 3px 3px 0 0; overflow: hidden; }
```

**自查：** hover 上去，然後盯著*陰影*看，不要盯卡片。如果你看不出陰影有變化，就一路往上翻祖先節點，找
`overflow: hidden`、`clip-path`，或是 `CanvasGroup` 那類的合成包裝層。用 `outline-offset` 畫的
焦點框也踩同一個坑。

---

### A2. 烘焙好的彈簧照 `Dv` 播，會播太快

**靜默症狀：** 動態的形狀是對的，但讀起來很趕，過衝變成一個急停而不是一次沉降。

```css
/* ❌ the curve is 0.32s long; the clock says 0.3s */
transition: translate .3s var(--spring-enter);
```

**為什麼會這樣寫：** token 表裡其他每一列都是時長，所以 `spring(0.3, 0.15)` 讀起來就像「0.3 秒」。
它不是。`Dv` 是*視覺*時長 —— 也就是動作看起來結束的那一刻 —— 而烘焙出來的曲線必然還包含後面那段沉降
尾巴。彈簧越彈，這兩個數字差越多：`b = 0.4` 時，尾巴佔總長的 35%。

```css
/* ✅ */
transition: translate .32s var(--spring-enter);   /* t_settle, from spring.md §4 */
```

**自查：** 在 `spring.md` 的 token 表裡，每一個彈簧都同時列了 `Dv` 和 `t_settle`。如果你 CSS 裡的
時長等於 `Dv`，那就是錯的。把 `Dv` 那些數值當作時長去 grep 你的樣式表 —— `.3s`、`.35s`、`.5s` ——
看它們旁邊是不是接著一個 `linear(` 緩動。

---

### A3. 進度被夾限，彈跳就靜靜消失了

**靜默症狀：** `b` 調了完全沒差。`spring(0.3, 0.15)` 和 `spring(0.3, 0.4)` 長得一模一樣，於是你
得出結論說彈跳太細微、沒意義，然後就不用了。

**為什麼會這樣寫：** 你採樣的部分做對了，但執行環境會拒絕或夾限 `0–1` 之外的緩動值。CSS 的 `linear()`
接受這種值；很多以列舉或曲線資產為基礎的系統不接受，而且它們是夾限，不是報錯。

**修法：** 一次搞清楚你在哪一種環境上，然後把它寫進轉接層。如果進度被夾限，那 `b > 0` 就無法透過烘焙曲線
達成 —— 要嘛去積分彈簧（`spring.md` §3），要嘛接受 `b = 0`，改從多屬性規則那裡拿到你要的生氣。

**自查：** 烘一條 `spring(0.3, 0.4)`，它的峰值是 `1.094`，拿去帶動一個 400px 的位移。如果元素從來
沒有跑超過 400px，那你的進度就是被夾限了。

---

### A4. 過場寫在 hover 狀態上，所以離開是瞬間的

**靜默症狀：** 進入 hover 很順，離開直接跳掉。你有一半的互動感覺沒問題，另一半覺得廉價，但你說不出為什麼。

```css
/* ❌ */
.card:hover { translate: 0 -4px; transition: translate .2s; }
```

**為什麼會這樣寫：** 它讀起來很自然 ——「hover 的時候往上移，花 0.2 秒」—— 而且在你測的那個方向確實有效。
但那條宣告只在選擇器命中時才存在，所以 hover 離開的當下，根本沒有過場可跑。

```css
/* ✅ the transition belongs to the resting state */
.card { transition: translate var(--t-micro); }
.card:hover { translate: 0 -4px; }
```

**自查：** 把指標移*開*，然後看。每個狀態都要測離開，不要只測進入 —— 這就是把 `feel.md` §5 套用到你
自己的測試流程上，而且它一次就抓得到 A4、A5 和 C1。

---

### A5. 進場完全沒動畫，因為根本沒有前一個值

**靜默症狀：** 元素就這樣直接出現。沒有錯誤，也沒有播到一半的動畫。

**為什麼會這樣寫：** 過場是在兩個計算值之間內插，而一個剛被插入 —— 或原本是 `display: none` —— 的元素，
沒有可以出發的第一個值。宣告本身沒問題；只是沒事情可做。

**修法：** 在 CSS 裡用 `@starting-style` 搭配 `transition-behavior: allow-discrete`
（`adapters/css.md`）。在腳本裡，先設起始值、強制一次重排、再設結束值 —— 就是那行看起來像空操作、但其實
不是的 `void el.offsetWidth`。在沒有這類機制的執行環境裡，就以起始值掛載，然後在下一幀改掉它。

**自查：** 如果某個進場動畫牽涉到一個上一幀還不存在的元素，那你就需要這三種做法之一。沒有第四種。

---

### A6. 動畫是在一個還完全透明的容器裡播完的

**靜默症狀：** 一個明明有在跑的效果 —— 你看得到 class 被套上、時間也對、飛行途中截圖也拍得到 ——
卻沒有任何一個讀者看見過。等到包住它的那個東西變得可見時，它早就播完了。

**為什麼會這樣寫：** 兩個相隔幾週寫下的捲動 observer，各自單獨看都沒錯。區塊在某個 threshold 淡入；
裡面的元素在另一個 threshold 動起來。兩段程式碼都沒提到對方，而這個 bug 只在兩者重疊的地方出現 ——
所以首屏那個沒有淡入祖先的元素跑得完美無缺，然後就被拿去當測試案例。

**修法：** 把它們排成序列。容器的進場先開始；裡面的內容跟在後面，偏移量要大到容器真的已經在畫面上。
在有父子編排機制的執行環境裡，這就是 `beforeChildren` 的用途（`feel.md` §6）；沒有的話，就是一個延遲。

**自查：** 對每一個進場動畫，問它的祖先在那個當下正在做什麼。只要其中任何一個正在淡入、正在縮放，或
還停在 opacity 0，你就中了這個 bug。**要在它實際會上線的位置測動畫，不是在頁面上第一個順手的位置測。**

---

### A7. 一個會換行的片語永遠達不到的 threshold

**靜默症狀：** 效果在某些元素上會觸發，某些不會，一開始看不出任何規律 —— 而失敗的都是比較長的那些。

```js
/* ❌ */
new IntersectionObserver(fn, { threshold: 0.5 }).observe(inlinePhrase)
```

**為什麼會這樣寫：** `0.5` 是反射性寫下的值，而它對一個區塊元素來說確實是對的。但一個跨兩行斷開的行內
元素，它的定界框是從第一段片段的開頭一路涵蓋到第二段片段的結尾 —— 而那個框裡大部分都是兩段行片段旁邊
的空白。被觀測到的比例是拿那個框算的，所以一個片語可以整個都在畫面上，卻永遠達不到你要求的 threshold。

**修法：** 行內目標就用低 threshold —— `0.1–0.25` —— 或者改成觀測一個 block 層級的包裹元素。而在「沒
觸發」的後果是內容看不見的地方（§A7 上面那則鄰居），再加上逾時保底。

**自查：** 把你其中一個測試片語弄到長得會換行。幾乎沒有人這樣做，所以這個 bug 才活得過 review。

---

### A8. 瀏覽器預設樣式表對這件事有意見，而你沒有覆蓋掉它

**靜默症狀：** 出現一個你調色盤裡根本沒有的顏色。一個完全沒有黃色的產品，highlight 卻是黃的；一個連結
留著你從來沒要求過的底線；一個控制項無視你的字體堆疊。

```css
/* ❌ 黃色還在，就在你那層 tint 底下 */
mark.fs {
  background-image: linear-gradient(var(--hl), var(--hl));
}
```

**為什麼會這樣寫：** 你設了你當時正在想的那個屬性。但瀏覽器早就設好了*另一個*畫在同一個位置的屬性 ——
你 `background-image` 底下的 `background-color`、你 `color` 旁邊的 `text-decoration`、表單控制項上
那個不會繼承的 `font`。你的宣告是對的，它也贏了它自己那場層疊；它只是沒有涵蓋整個表面。

```css
/* ✅ */
mark.fs {
  background-color: transparent;
  background-image: linear-gradient(var(--hl), var(--hl));
}
```

**自查：** 任何你動過樣式、而且帶有原生語意的元素 —— `mark`、`button`、`input`、`fieldset`、
`summary`、`dialog`、`progress`、`a` —— 把你自己的樣式關掉，看它一次。你在那裡看到的東西，就是你正在
往上蓋的東西，而其中任何一個你沒有明確指名的部分，都還留在底下。

---

### A9. 用視窗單位設定的展示級字體，是照拉丁文調出來的

**靜默症狀：** 一個標題在英文下是對的，到了中文、日文或韓文就垮掉 —— 兩個字就斷行，或斷在一個不該被切開
的詞中間。它不會溢出，所以截圖裡看不出哪裡明顯壞掉；它只是讀起來很隨便。

```css
/* ❌ 對著一個拉丁文標題用眼睛挑出來的 */
h1 { font-size: clamp(46px, 8vw, 92px); }
```

**為什麼會這樣寫：** 你是拉著視窗、看著標題裡的英文，挑出那個視窗單位係數的。拉丁文字身窄，而且它的行是在
空格處斷的 —— 尺寸只要稍微太大，馬上就會看到一個詞換行換得很難看。CJK 兩者都沒有：每個字都是一個 em 寬，
而且任兩個字之間都可以斷行。太大不會產生一個明顯的斷行；它產生的是一個任意的斷行，而這種東西活得過
review，因為它看起來還是像一行字。

**修法：** CJK 的展示級字體，大小抓得比你調出來的拉丁文設定小 25–35%，而且 `clamp()` 的最大值要對著
**這個標題有史以來會佔到的最窄那一欄**來挑 —— 包含你為了某個裝飾性東西預留的任何留白（`contrast.md`
§8 把「預留一道」訂成規則，而預留它正是這裡那一欄變窄的原因）。

**自查：** 每一個 `clamp()` 標題，都在剛好高於各個斷點的寬度下看一次，用你有出貨的語言裡字身最寬的那一種。
不是在你自己的視窗大小下，也不是用英文。

## B. 你違反了這包文件白紙黑字寫過的規則

### B1. 用版面屬性去移動東西

**靜默症狀：** 動起來看似正確，但在中階手機上掉幀，在你的機器上一切正常。

```js
/* ❌ — and this was written by someone implementing this very pack */
flier.style.transition = "left .32s var(--spring), top .32s var(--spring), width .32s, height .32s";
flier.style.left = to.left + "px";
```

**為什麼會這樣寫：** 你手上有兩個從 `getBoundingClientRect()` 拿到的矩形，而它們就是用
`left`/`top`/`width`/`height` 表達的。直接動畫你已經握在手裡的數字，是從量測走到動態最短的一條路，
而且做出來的形狀是對的，所以沒有任何東西提醒你回頭再看一眼。

```js
/* ✅ place it at the destination, move it with a transform */
flier.style.left = to.left + "px";
flier.style.top = to.top + "px";
flier.style.width = to.width + "px";
flier.style.height = to.height + "px";
flier.style.translate = (from.left - to.left) + "px " + (from.top - to.top) + "px";
flier.style.scale = from.width / to.width;
/* next frame: animate both back to identity */
```

**自查：** 把你寫過的每一段動畫拿去 grep `left`、`top`、`width`、`height`、`margin`、`padding`。
每一個命中都必須有理由。`feel.md` §4 那套「量測再反推」的流程存在的目的，就是讓答案永遠是 transform。

---

### B2. 一個事件，只動一個屬性

**靜默症狀：** 互動有反應，但沒人講得出它在表達什麼。回報通常就是一句「感覺很廉價」，沒有下文。

**為什麼會這樣寫：** 每個屬性是在不同時間點加進去的。位移是你在做元件時放的；陰影是設計審查的一條註記；
表面變化在某次重構裡不見了。單看任何一個 commit 都不覺得有問題。

**修法：** 把 `SKILL.md` §3.5 那些列當成最低標，不是菜單。抬起是位移**加上**更大更柔的陰影**加上**更亮的
表面。按壓是縮小**加上**更緊的陰影**加上**變暗。

**自查：** 數一下每個互動有幾個屬性在變。抬起或按壓少於三個，就代表還沒做完 —— 而且如果三個裡面有一個是
陰影，回頭再跑一次 A1 的自查，因為陰影就是在那裡靜靜消失的。

---

### B3. 對稱的退場

**靜默症狀：** 整個介面到處都覺得有點拖，但你指不出哪一個具體的慢動作。

**為什麼會這樣寫：** 退場通常是照進場鏡射寫出來的，因為那是改一次而不是改兩次，而且它也不算*錯* —— 只是
長了 40%，距離還是必要值的兩倍多。

**修法：** 退場用進場時長的 `0.5–0.7×`，距離減半或更短，curve 用 `in`。

**自查：** 把你 token 集裡每一個退場時長找出來，跟對應的進場比一比。這是一個兩分鐘的稽核，而它會改變整個
產品的手感。

---

### B4. 兩套彈簧語彙混用

**靜默症狀：** 你的其中一個參數毫無作用。你調 `bounce` 看不出差別，於是你以為值太小，就一路加到有東西動
為止。

```js
/* ❌ */
{ type: "spring", visualDuration: 0.3, bounce: 0.2, stiffness: 400 }
```

**為什麼會這樣寫：** 你接手了一個用 `stiffness` 寫的彈簧，想調手感，就伸手去拿你看得懂的那個參數 ——
然後把舊的留在原地。大多數實作處理這種情況的方式，是靜靜忽略掉其中一套。

**修法：** 一個專案只用一套語彙。優先用 `Dv`/`b`；要換算就在邊界上用 `spring.md` §2 的做法。

**自查：** grep `stiffness` 和 `damping`。每一個命中都應該落在換算函式裡面，其他地方一個都不該有。

---

### B5. 一個 shorthand、一個 timing function，以及每一個你當時沒在想的階段

**靜默症狀：** 一段多階段動畫，中間是對的，結尾卻硬生生停死。讀者的說法是「那個淡出看起來怪怪的」，然後
就講不出更多，因為出錯的那個階段正是沒人在看的那個。

```css
/* ❌ 除了那個把它蓋掉的 keyframe 以外，每一段都是 linear */
animation: first-sight 1s linear both;
@keyframes first-sight {
  0%   { …; animation-timing-function: cubic-bezier(.25,.1,.35,1); }
  30%  { … }
  60%  { … }
  100% { … }
}
```

**為什麼會這樣寫：** shorthand 需要*一個* timing function，`linear` 是聽起來最中性的那個，然後你就
去把你真正在設計的那個階段做緩動。其他每一個階段都靜靜繼承了 `linear` —— 而任何有起有停的東西用
`linear`，正是 `feel.md` §10 點名的反面模式。

```css
/* ✅ 每一個開啟一個段落的 keyframe 都給一個 function */
0%   { …; animation-timing-function: cubic-bezier(.25,.1,.35,1); }  /* 抹掃 */
30%  { …; animation-timing-function: linear; }                      /* 停頓：什麼都不動 */
60%  { …; animation-timing-function: cubic-bezier(.25,.1,.35,1); }  /* 沉降 */
100% { … }
```

**另外值得單獨注意：** 這包文件自己的 `recipes.md` §26 為那段沉降指定了 `curve out`，而實作出貨的是
`linear`。**規格是對的，程式碼是錯的，而任何工具鏈裡都沒有東西會去比對這兩者。** 只要有一份文件寫下了
某個程式碼應該持有的數字，那份一致就是靠某個人同時讀兩邊維持的 —— 所以把那個數字寫進程式碼旁邊的註解裡，
讓下一個人不用特地跑去查就會看到。

**自查：** 數一數 keyframes 裡的 timing function。每一個段落邊界要有一個，不然你就是在繼承 shorthand
的那個 —— 然後把 recipe 和程式碼並排讀一次，必要的話唸出聲。

---

## C. 你把邏輯掛在動畫上

### C1. 在完成事件裡移除節點

**靜默症狀：** 看不見的元素在節點樹裡越積越多，還會攔截點擊。這只會發生在操作很快的使用者身上，所以你盯著
看的時候它不會重現。

```js
/* ❌ */
el.addEventListener("transitionend", () => el.remove());
```

**為什麼會這樣寫：** 這就是為此而生的官方事件，而且你每次測都會過 —— 因為你的測法是點一下然後等。

```js
/* ✅ the animation is presentation; the removal is not */
el.classList.add("leaving");
setTimeout(() => el.remove(), EXIT_MS);
```

**原因：** 動畫被取消、中斷、取代，或在減少動態下被略過時，完成事件不會觸發 —— 而以 promise 為基礎的
API 在這些情況下會*拒絕*，所以一個沒被 catch 的 `await` 會讓節點永遠留著。這四種全都是正常狀況，不是
邊界案例。

**自查：** 觸發退場，然後立刻再觸發一次，或在半途反向。接著檢查節點樹。另外：把減少動態打開，確認東西還是
會被移除。

---

### C2. 把動畫當成真相來源

**靜默症狀：** 一個選單在過場被中斷之後，既不算開也不算關，接下來那次切換就做了錯的事。

**為什麼會這樣寫：** 視覺狀態和邏輯狀態看起來是同一件事實，所以只留一個變數看起來像是好習慣。

**修法：** 布林值留著。動畫朝著它跑。`pitfalls.md` §7 的測試講得很精準：**如果你把產品裡所有動畫全部
刪掉，所有邏輯都應該照常運作。**

**自查：** 把每一個時長設成 `0.01ms`，然後用一遍產品。所有東西都該還能動。接著把它們設成 `2s`，再去
中斷各種東西。答案要一樣。

---

## D. 你相信了某個你沒有驗證過的東西

### D1. 憑記憶寫出來的 API 名稱

**靜默症狀：** 有防護的讀取，什麼都不會發生 —— 防護把它吞了，功能就永久關閉。沒有防護的讀取，則是在某條
沒人走過的程式碼路徑上崩潰。

```lua
-- ❌ the guard makes a wrong name indistinguishable from an absent one
local ok = pcall(function() reduced = GuiService.ReducedMotion end)
```

**為什麼會這樣寫：** 名字*幾乎*是對的，而防禦性寫法是個好習慣。這兩件事加在一起，產出一個靜默缺席的功能
—— 所有結果裡最糟的一個，因為它看起來像是被處理好了。

**自查：** 出貨前去平台自己的 API 清單裡把名字讀出來，不要從你對它的記憶裡讀。防護是給那種*在舊版用戶端上
可能不存在*的屬性用的；它不能拿來取代「知道名字」。如果有防護的讀取失敗了，在開發環境把它記錄下來，不要
默默退回預設值。

---

### D2. 宣稱一個文件根本沒給的保證

**靜默症狀：** 沒有症狀，直到有人在這個說法上蓋東西。然後你會遇到一個 bug，追下去的源頭是某份文件裡的一句
話，而不是任何一行程式碼。

**為什麼會這樣寫：** 一個明顯*應該*處理某情況的元件通常真的有處理，而且寫「handles X」比寫「這件事你自己
驗證」短。

**修法：** 文件寫什麼，你就寫什麼。你相信某件事為真但拿不出出處時，就照這個意思講出來，並說明怎麼驗證。

**自查：** 你寫的每一句能力宣稱，都問自己一次：這是在哪讀到的？「照理說應該是」不算出處。

---

### D3. 你手工生出來的數字

**靜默症狀：** 一條*大致上*正確的曲線。它會動，看起來像彈簧，而它錯的地方沒有任何審查者光用讀的抓得到。

**為什麼會這樣寫：** 一張 21 個值的緩動表，看起來就像那種可以照形狀估出來的東西，而估出來的結果也夠像樣，
足以騙過一眼掃過。

**修法：** 算出來。`spring.md` §4 給了每種阻尼區間的封閉解；十行腳本就能產出那張表。然後拿端點和峰值去
對照已公布的數字。

**自查：** 兩個不變量幾乎抓得到所有問題 —— 表必須恰好從 `0` 開始、恰好在 `1` 結束，而它的峰值必須符合
`spring.md` §1 裡那個 `b` 對應的過衝量。一條「有彈性」的曲線如果在回程時從來沒有掉到 1 *以下*，它就不是
彈簧，它是一條手畫的弧線。

---

## E. 文件本身的紀律

### E1. 在一份與執行環境無關的檔案裡出現了函式庫識別字

**靜默症狀：** 一個句子突然讀不通，而讀者被送去找一個在他的執行環境裡根本不存在的 API。

> ❌ Items inside: `stagger 0.03`, starting after the container is `beforeChildren`.

**為什麼會這樣寫：** 這條規則是從某一個實作學來的，而那個實作對它的稱呼比規則本身短。當周圍的文字被改寫成
中立說法時，那個識別字會活下來，因為它看起來像個專業術語。

> ✅ 容器內的項目：`stagger 0.03`，而且要等容器完全展開後才開始 —— 也就是 `feel.md` §6 的
> 「容器先於子項」規則。

**自查：** 拿任何特定函式庫的詞彙，去 grep 那些談判斷的章節。一份開頭就承諾不點名任何 API 的檔案，應該
要能證明這件事。

---

### E2. 指到錯誤章節的交叉引用

**靜默症狀：** 讀者順著指引過去，看到不相干的內容，然後就安靜地連帶不再信任其他引用。

**自查：** 你寫的每一個 `§N`，都去把 §N 打開。機械、無聊，而且是這份檔案裡命中率最高的一項自查 ——
交叉引用每次文件重組都會爛掉，而工具鏈裡沒有任何東西會發現。
