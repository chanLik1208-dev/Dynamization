# feel.md — 動態怎麼做才會讀起來像真的

這份文件不談 API。它談的是*為什麼那個動畫看起來很假*。

大致依照「破壞真實感的嚴重程度」排序：**先修前面的，後面那些細節要等前面對了才有意義。**

這裡所有東西都用 `SKILL.md` §1 的規格詞彙寫成。內容不綁任何平台。

---

## 0. 一句話原則

> 動畫要讓人**不必動腦**就知道剛剛發生了什麼事。
> 使用者不該注意到動畫。他們該注意到的是*那東西是從那裡來的*。

任何會讓人停下來*欣賞*的動畫，放在產品裡幾乎一定太長。

---

## 1. 讓正在被動畫的那個值決定參數

不確定該用什麼的時候，**不要自己發明**。看*動的是哪一類的值*，選擇其實已經幫你做好了：

| 動的是什麼 | 用 |
|---|---|
| 三個以上的 keyframe | tween、`dur 0.8`、curve `inout` |
| 位置與旋轉 — `x` `y` `z` `rotate` `skew` | `spring(0.28, 0.2)` — 輕微過衝 |
| scale 家族 | `spring(0.27, 0)` — **不過衝** |
| 其他全部 — 透明度、顏色、模糊、濾鏡 | tween、`dur 0.3`、curve `out` |

最後一列的曲線值得講精確一點：那是一條**比平台預設更平緩的 easeOut** — 起始沒那麼突兀，結尾一樣柔。用 cubic-Bézier 講是 `(0.25, 0.1, 0.35, 1)`；在有具名曲線的執行環境裡，選「sine out」或「quad out」，不要「quint out」。

**從那張表可以直接讀出三個結論：**

1. 佔空間的東西（位置、尺寸）→ 彈簧。不佔空間的（透明度、顏色）→ tween。
2. 放大縮小**不該彈**。移動可以。
3. 預設時長只有 `0.3s`。你的比這長，就要有理由。

---

## 2. 彈簧真正的價值是速度接續，不是彈性

大部分人以為 spring = 會彈。錯。最要緊的性質是：**動畫被中斷時，它會從當下的位置、以當下的速度繼續走** — 而不是硬生生停住再重來。

這就是*像個實體物件*跟*像投影片*之間的分界線。

想像一個值在兩個目標之間來回切換，切換速度比動畫跑完還快：

- **tween** 每次切換都硬重啟。每次重啟都從零速度開始，所以動態會在使用者操作的那一瞬間明顯卡一下 — 而那正是他們盯著看的瞬間。
- **彈簧**目標被移動時會保留位置與速度。反向的手感就像推一個有慣性的東西，因為積分做的事情就是這個。

**判斷方法：這個動畫是不是由使用者的直接操作觸發的？**

| 觸發方式 | 用 | 為什麼 |
|---|---|---|
| 拖曳、滑動、手勢、跟隨游標 | **彈簧**（強制） | 有真實速度要接續 |
| 點擊 / 懸停造成的移動或縮放 | **彈簧** | 會被反覆中斷 |
| 切換造成的版面變化 | **彈簧** | 同上 |
| 進場 / 出場淡入淡出 | **tween** | 沒有速度要接續；時間可控比較重要 |
| 任何需要對時的（stagger、序列、影片） | **tween** | 彈簧沒有可靠的結束時間 |
| 捲動連動 | 先直接綁定，再平滑化 | 見 §7 |

在 **Tier 2** 執行環境（見 `SKILL.md` §2）上你還是能中斷，但速度會遺失。兩個補救手段，依優先順序：對真正靠手勢驅動的那少數幾個互動，手寫彈簧積分（`spring.md` §3 — 十五行而已）；其他地方則在中斷的當下讀取**當前**值，從那裡用 `b ≤ 0.15` 動過去，重啟幅度小到不會被讀成卡頓。

在 **Tier 3** 上別硬撐。把可重複觸發的動畫壓在 `dur ≤ 0.2s`；低於這個門檻，硬重啟落在知覺底線以下，沒人看得出來。

## 3. 用 `Dv` + `b` 調，絕不用原始係數

沒人想像得出 `stiffness: 400, damping: 32` 長什麼樣，而且這兩個旋鈕會互相牽動 — 所以「再快一點點」會變成整組重設計。用視覺時長與彈跳量來工作，只在邊界轉換一次。

完整換算、各個 bounce 值實際會產生多少過衝，以及積分器 → `references/spring.md`。

簡短版：

- `b` 是*過衝多少*：`0.15` 大約超過目標 0.6%，`0.4` 大約 9.5%。
- `Dv` 是*看起來花多久* — 尾巴發生在那之後，這也正是彈簧跟 tween 能互相對齊的原因。
- scale 永遠 `b = 0`。
- 一個產品一個 `b`。彈跳量混雜，是「這介面由好幾個從沒講過話的人拼出來」最明顯的破綻。

## 4. 因果：東西要從它來的地方來

這條破了，曲線再怎麼打磨都救不回來。

- 下拉選單要**從打開它的控制項**展開，而不是從螢幕中央淡入。把 transform origin（或錨點）放在那個控制項上。
- 對話框要從被點的那張卡片長出來。如果你的執行環境能把一個元素動畫到另一個元素的位置，就用；不能的話，至少讓對話框從卡片的位置與尺寸開始移動過去，而不是淡入。
- 側邊欄要**從它自己那一側**滑進來，不是從下面。
- 刪掉一個列表項目，其他項目要**把留下的空隙收攏**，不是用跳的。
- toast 要從它最後停駐的那個角落進場。

**共享元素的通用做法**，用在沒有內建支援的執行環境裡：

```
1. measure the source rect before the change      (position, size)
2. let the layout change happen instantly
3. measure the destination rect
4. apply the inverse transform to put it visually back at the source
5. animate that transform to identity
```

只有 transform 在動，所以這件事對合成器來說很便宜，儘管它看起來像版面動畫。任何能量測矩形、能套用 transform 的執行環境都做得到，也就是全部。

**travel 距離的量級感：**微互動 `4–12px`、元件轉場 `16–40px`，百分比只留給全螢幕的移動。

從 `y: 100` 淡入是最常見的錯誤 — 對一個 tooltip 來說，那個距離讀起來是*從另一個房間走過來*。

## 5. 進場與出場不對稱

| | 進場 | 出場 |
|---|---|---|
| 時長 | `0.2 – 0.35s` | 進場的 **0.5 – 0.7×** |
| 曲線 | `out` / 彈簧 | `in` |
| 距離 | 完整 | **一半或更少** |
| 起始縮放 | `0.95`（不是 `0`） | `0.98`（幾乎不縮） |

理由：進場時使用者要*接住*新資訊，需要時間定位它。出場時那東西對他們已經沒有意義了，還讓他們等就是浪費他們的時間。

進場 `out`、出場 `in`，整段體驗合起來就是一個整體的 `inout`。

絕不要從 `scale: 0` 進場。那代表*從無到有*，但介面元素幾乎都是*從別的地方來的*。`0.95` 已經足夠說出「這東西出現了」。

**需要機制的是出場。**進場動畫很簡單 — 東西在那裡，動它就好。出場則需要在某個東西邏輯上已經被移除之後，還讓它活著。每個執行環境解法都不一樣，而這正是「出場動畫都不會播」的頭號成因。設計出場*之前*就先在你的 adapter 裡找到那個機制，不要事後才找。

## 6. 編排：stagger 是節奏，不是裝飾

十個東西同時出現，讀起來就是一坨。錯開它們，你就得到了順序，還有方向。

**間隔怎麼選：**

| 項目數量 | 間隔 | 總預算 |
|---|---|---|
| 3–6（選單、卡片列） | `0.04 – 0.06s` | ≤ 0.35s |
| 7–15（列表） | `0.02 – 0.04s` | ≤ 0.5s |
| 逐字 | `0.02 – 0.03s` | 看長度；超過 1s 就改成逐詞 |
| > 20 | 別逐項錯開 | 分組，或整塊一起淡入 |

**總時長是硬上限。**20 個項目用 `0.1s` 錯開就是 2 秒 — 等最後一個落定，使用者早就在做別的事了。寫之前先把算術做完。

**方向要有意義：**
- **from first** — 由上到下，符合閱讀順序，安全牌
- **from last** — 收合時用，看起來像捲回去
- **from centre** — 向外展開，儀式感，適合 hero 區塊
- **from the item the user just touched** — 由此向外擴散 ← **能做到的最強因果陳述**，而且幾乎沒人在用

**容器先於子項，子項先於容器。**容器要先打開，內容才倒進來；內容要先清空，容器才關上。如果你的執行環境沒有父子編排，這就只是兩個延遲加一次算術檢查：容器的出場不能早於子項出場結束。

## 7. 捲動：連動的必須平滑，觸發的必須只放一次

**捲動觸發**（進入視窗時播放）

**只放一次。**這幾乎永遠是對的 — 使用者來回捲動就重播的動畫會讓人反胃，而且第二次播也不帶任何資訊。

在大約**露出 30%** 時觸發，不是第一個像素。一個像素的門檻會在元素還貼在螢幕最邊緣時就觸發，等它真的進到視野裡，動畫早就播完了。

**捲動連動**（一個值綁定到捲動位置）

捲動輸入是離散的 — 一格滾輪、一次觸控板事件、一幀的觸控位移。直接綁到 transform 上會產生看得見的階梯感。**讓它過一層彈簧是必要的，不是加分項**：跑一個彈簧，每一幀把它的 `target` 重設為捲動值，然後用彈簧的輸出去動。

這裡要用*軟*的彈簧 — 大約 `spring(0.35, 0)`。它是濾波器，不是運動；捲動連動的值上出現過衝，讀起來就是頁面在跟使用者作對。

兩個一定會咬人的細節：

- 掛載時彈簧必須**以當前捲動值初始化**，不能是零，否則頁面載入時會從頂端整個掃下來。
- 釘住元素請用平台原生的 sticky/anchor 機制，絕不要在捲動處理函式裡每幀寫入一次位置。

**視差幅度**：背景圖層用前景的 `0.3–0.5×` 就很夠了。再多就不會被讀成深度，而是讀成*背景在漂*。

減少動態時，視差是第一個該關掉的東西。

## 8. 手勢回饋必須在 100ms 內開始

觸控與點擊回饋是**確認訊號**，不是動畫。

```
hover:  scale 1.03      spring(0.15, 0)
press:  scale 0.97      spring(0.15, 0)
drag:   scale 1.03  +  wide shadow  +  raised depth order
```

- **按下 = 變小。**手指往下壓，東西就該被壓下去。變大是錯的物理。
- hover 縮放上限抓 `1.05`；再多，旁邊的元素看起來像被擠開。
- 大元素（卡片、面板）需要*更小*的 hover 縮放（`1.01–1.02`），因為實際位移 = 縮放 × 尺寸，同樣的比例在大元素上移動的距離大得多。
- 拖曳一定要有明確的「被抓住」狀態，使用者才知道自己抓到了。
- 邊界要**用彈性表達**：讓使用者稍微拉過界 — 阻力隨距離上升，通常過界後只走一半的輸入量 — 放開就彈回去。硬牆讀起來像 bug；彈性阻力讀起來像規則。
- 不管你的按壓回饋是什麼機制，確認它在**鍵盤啟動**時也會觸發。一個滑鼠點擊會明顯壓下去、按 Enter 卻毫無反應的按鈕，比從來不會壓下去的按鈕更糟。

## 9. 等待與不確定

- **1 秒以內**：不要轉圈。一閃而過的轉圈比乾等更煩人。
- **1–5 秒**：骨架屏。它的微光要慢（每趟 `1.5–2s`）而且低對比 — 它是在說*我還在*，不該來搶注意力。
- **超過 5 秒，或進度已知**：進度條，而且**絕不倒退**。
- 用樂觀更新時，直接以最終樣貌插入新項目（可以降低透明度），只有失敗時才動畫回滾。**讓成功路徑完全看不見，是最好的動畫。**

環境型的循環效果（呼吸、脈動、微光）：幅度小到*察覺得到但讀不出來*，週期 `≥ 1.5s`，而且在減少動態時一律關閉。

## 10. 反模式

| 反模式 | 為什麼錯 | 改成 |
|---|---|---|
| 全部都 `dur 0.5` | 沒有分層：如果每件事都一樣重要，就等於都不重要 | `SKILL.md` §3.4 的時間分層 |
| 從 `y: 100` / `scale: 0` 淡入 | 距離太大；讀起來像從另一個畫面走過來 | `y 8–16px`、`scale 0.95` |
| 讓 scale 彈跳 | 撞玻璃的手感 | `b = 0` |
| 移動用 `linear` | 現實世界沒有任何東西是等速起停的 | `out` 或彈簧；`linear` 只留給捲動連動和無限旋轉 |
| 出場跟進場一樣長 | 讓人為了已經沒意義的東西等待 | 出場砍到 0.5–0.7× |
| 捲動觸發的動畫會重播 | 讓人反胃，而且第二次不帶資訊 | 只放一次 |
| stagger 沒算術 | 最後一項晚兩秒才落定 | 間隔 × 數量 ≤ 0.5s |
| 動 width / height / top / left | 觸發重排，掉幀 | 用 transform，加上 §4 的量測反推法 |
| 用不可取消的計時器串接 | 無法中斷，而且會飄 | 一個能整組取消的序列 |
| 只在淺色主題測過 | 陰影在深色表面上根本看不見 | 見 `contrast.md` |
| 沒處理減少動態 | 會讓某些使用者暈眩 | `SKILL.md` §5 |
| 同一頁上同時有 `b = 0` 和 `b = 0.4` | 介面看起來是東拼西湊的 | 整個產品一組 token |
| 拿「動畫結束」callback 來跑真正的邏輯 | 被中斷就永遠不會觸發 | 狀態獨立驅動；動畫只是呈現 |

## 11. 定義 token；別再手調

自然感的另一半是**一致性**。在同一個產品裡，意義相同的動作應該共用同樣的時長與曲線。這個東西寫一次就好，格式用你的執行環境的設定檔格式：

```
feedback :  dur 0.12   curve out          # press, checkbox, focus ring
micro    :  dur 0.2    curve out          # hover, tooltip
enter    :  spring(0.3,  0.15)            # component entry
exit     :  dur 0.15   curve in           # component exit
layout   :  spring(0.35, 0)               # reflow
page     :  spring(0.5,  0.1)             # route change
stagger  :  0.04
lumin    :  dur 0.13   curve out          # brightness, colour, shadow tier
```

注意最後一列：亮度有自己的 token，因為它必須**比它所伴隨的移動更快**（`contrast.md` §5）。如果你的 token 組裡沒有亮度這一項，亮度最後就會跟移動共用時長，讀起來會變成*顏色在追著物件跑*。

之後，只在真的需要偏離時才在單一元件裡覆寫 — 而且只在你講得出理由的時候。
