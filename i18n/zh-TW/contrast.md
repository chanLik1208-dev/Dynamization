# contrast.md — 明暗的表現力

動態是**時間**的語言：東西從哪裡來、往哪裡去。
亮度是**空間**的語言：什麼疊在上面、什麼是活的、現在該看哪裡。

兩者單獨都只做了一半的工。**所謂「浮起來」，不是把東西往上推 8px，而是上移 4px ＋ 更大、更柔的陰影 ＋ 更亮的表面——三件事同時發生，大腦才會終於讀成*它靠近我了*。** 這份文件講的就是怎麼把亮度接進動態裡。

這裡談的光學原理跟平台無關。只有 §6 提到具體的屬性，而且也只是拿來當例子，說明每個算繪器都存在的成本階層。

---

## 1. 心智模型：光從上面來

人的視覺預設光源在頭頂。每一個亮度決策都建立在這件事上，違背它就會顯得詭異或廉價。

| 要表達 | 亮度安排 |
|---|---|
| **凸起**（按鈕、卡片、popover） | 頂緣一道淡淡的亮邊（rim light）＋ 下方的陰影 |
| **凹陷**（輸入框、插槽、按下狀態） | 頂部的內陰影 ＋ 底部淡淡的亮度 |
| **齊平**（背景、分隔線） | 完全不用陰影，只靠表面明度的差異 |
| **高高浮著**（對話框、拖曳中） | 一層寬、低不透明度、模糊得很開的陰影 |

層級越高，陰影就該**更大、更柔、更淡**——不是更黑。

新手最常犯的錯，是把陰影的黑加深來表達「更高」，但那讀起來只會是*更髒*。正確的做法是加大**模糊**和 **y 位移**，同時**降低** alpha。

四階的階梯，寫成 位移 / 模糊 / alpha——不管你用什麼形式表達，數字就是這些：

| 階 | 意義 | 接觸層 | 環境層 |
|---|---|---|---|
| **e1** | 貼在表面上 | `0 1px 2px  / 8%` | — |
| **e2** | 卡片 | `0 1px 2px  / 5%` | `0 2px 6px  / 7%` |
| **e3** | popover、下拉選單 | `0 2px 6px  / 5%` | `0 8px 20px / 6%` |
| **e4** | 對話框、拖曳中 | `0 4px 12px / 4%` | `0 20px 48px / 5%` |

雙層結構才是重點：一層緊貼的（**接觸陰影**，說明這個物件有厚度），一層寬而散的（**環境遮蔽**，說明它離多遠）。單層陰影永遠看起來像貼紙。

**如果你的算繪器沒有陰影原生功能**——多數遊戲和 3D UI 執行環境都沒有——一樣可以用兩張疊在元素後面的 nine-slice 圖做出這兩層：一張小而緊、大約就是元素本身的矩形再往外幾個像素，一張大而模糊、往外撐得遠遠的。動的是它們的 *alpha*，永遠不要動尺寸。這份文件其他部分完全照用。

## 2. 暗色主題用另一套機制表達層級——這一段最常被做錯

**在深色表面上，陰影是看不見的。** 黑色陰影投在接近全黑的底上，根本沒有對比可用。

把淺色主題的陰影原封不動搬進暗色主題，結果就是*每一層都消失，整個畫面變平*。

暗色主題用的是相反的機制：**越高的表面越亮。**（物理上的直覺是：離光源越近的表面，接收到的光越多。）

| 圖層 | 淺色主題 | 暗色主題 |
|---|---|---|
| 背景 | `#FFFFFF` | `#0E0E10` |
| 表面／卡片 | `#FFFFFF` ＋ e2 | `#17171A`（約亮 5%） |
| Popover／下拉選單 | `#FFFFFF` ＋ e3 | `#1F1F23`（約亮 8%） |
| Modal | `#FFFFFF` ＋ e4 | `#26262B`（約亮 12%） |

**所以切換主題不是換一組色票，而是換掉「表達層級」的那套機制。** 一組正確的 token 會同時換掉兩件事：

| Token | 淺色 | 暗色 |
|---|---|---|
| `surface` | `#FFFFFF` | `#0E0E10` |
| `elevated` | `#FFFFFF`（相同——高度是陰影給的） | `#1F1F23`（**不同**——高度是從這裡來的） |
| `shadow-e2` | `0 2px 6px / 7%` ＋ `0 1px 2px / 5%` | `0 2px 8px / 50%`——仍然把物件錨在畫面上，但不再負責層級 |
| `rim` | inset top `1px` white `60%` | inset top `1px` white `7%`——**弱非常多** |

`rim` 那一列是最常被忘掉的。一道為淺色主題調好的亮頂緣，放到深色表面上會變成一條發光的白色髮絲線。

暗色主題還有三條實務規則：

- **不要用純黑。** 在 OLED 上，內容和背景的邊界會糊掉，而且純黑上的白字在高對比下很刺眼。落在 `#0E–#14` 這個區間會舒服得多。
- **內文不要用純白。** 降到 `#E8E8EA` 附近，長文閱讀會輕鬆很多。
- **把飽和色降飽和、調亮。** 為淺色主題調過的品牌色，放到深色底上通常會螢光到刺眼。

## 3. 對比的三種工作——不要混在一起

| 工作 | 手法 | 不要這樣做 |
|---|---|---|
| **層級**（誰在上面） | 表面亮度 ＋ 陰影 | 邊框（邊框說的是*分隔*，不是*高度*） |
| **焦點**（要看哪裡） | 把其他東西壓暗（scrim） | 把目標調更亮（一場軍備競賽，結局是全部都亮） |
| **狀態**（活著／停用／選取） | 明確的顏色 token | 只靠不透明度（見下） |

**焦點靠壓暗周圍達成，不是靠調亮目標。** 一個畫面撐得起的亮點就那麼幾個，所以調亮這條路很快就走不下去。壓暗永遠有效，因為對比是相對的。

**不要用 50% 不透明度表達停用。** 半透明的元素會吃進背後的任何東西，所以在不同背景上會長得不一樣，而且會把文字對比拖到看不清楚。用一個專屬的 `text-disabled` token。

材質——剖面線、顆粒——不是第四種工作。它強化的是第一種，順便替頁面加個重音，而且受 §8 那些限制約束。如果你伸手去拿它，是為了做這張清單上的某件工作，那你拿錯工具了。

## 4. 把亮度接進動態：複合表達

這才是「強化表達」真正的意思——單一屬性帶的資訊太少，**只有同方向、多屬性一起變，才會被讀成一個物理事件。**

以下每一項都寫成規格，可以直接交給任何執行環境。

### Lift（卡片 hover）

| 通道 | From → To | 時序 |
|---|---|---|
| `y` | `0 → −4px` | `spring(0.2, 0)` |
| `scale` | `1 → 1.01` | `spring(0.2, 0)` |
| 陰影 | `e2 → e3`（更大更柔，**不是更黑**） | `dur 0.2  curve out` |
| 表面 | `surface → surface-hover`（淺色：幾乎不動／暗色：**更亮**） | `dur 0.2  curve out` |

位移需要 spring，因為它隨時可能被移開的游標打斷。亮度不需要——那裡用單純的 tween 才對，而且沿著這條線把兩者拆開，在多數執行環境裡都是最省力的做法。如果你的平台有便宜的宣告式狀態層（CSS `:hover`、樣式表、UI 狀態機），就把亮度放進去，程式碼裡只留位移。

### Press（凹下）

| 通道 | From → To | 時序 |
|---|---|---|
| `scale` | `1 → 0.97` | `spring(0.15, 0)` |
| 陰影 | `e2 → e1` **加上**頂部 `1–2px`、黑 `12%` 的內陰影 | `dur 0.1  curve out` |
| 亮度 | `1 → 0.96` | `dur 0.1  curve out` |

**縮小 ＋ 變暗 ＋ 陰影收縮**三者合起來，才是*被壓進去*。單獨縮小只代表*變小了*——那是完全不同的一句話。

### Dragging（被拿起來）

| 通道 | From → To | 時序 |
|---|---|---|
| `scale` | `1 → 1.04` | `spring(0.2, 0)` |
| 陰影 | `e2 → e4`，誇張化：`0 24px 48px / 18%` | `dur 0.15  curve out` |
| 深度順序 | 抬到同層兄弟之上 | 立即 |

拖曳是唯一適合誇張陰影的場合——物件必須明顯離開平面，否則使用者不確定自己到底抓住了沒有。

### Modal 開啟（聚焦）

壓暗和內容同時開始，但**背景先落地**：

| 通道 | From → To | 時序 |
|---|---|---|
| scrim 不透明度 | `0 → 1` | `dur 0.2  curve out` ← 最先完成 |
| dialog 不透明度 | `0 → 1` | `dur 0.2  curve out` |
| dialog `scale` | `0.96 → 1` | `spring(0.28, 0.1)` |
| dialog `y` | `+8px → 0` | `spring(0.28, 0.1)` |

離場反過來，並套用 `feel.md` §5 的不對稱原則：`dur 0.15`、`scale → 0.98`、`y → +4px`，而 scrim **最後**才離開。

Scrim 的數值：淺色主題用黑色 `40–50%`。暗色主題必須**換個做法**——50% 的黑蓋在接近全黑的底上什麼也做不到，所以要嘛把不透明度拉高很多，要嘛反過來把 dialog 本身調亮來拉開對比。

背景模糊在哪個平台都貴（它會把底下整層重繪或重新取樣）。小面積沒問題；全螢幕請實測，並考慮在低階裝置上改出扁平的 scrim。

## 5. 亮度變得比位移快

亮度是**狀態訊號**；位移是**過程**。狀態應該立刻確認；過程則可以慢慢來。

| 變化 | 時長 |
|---|---|
| 亮度／換色 | `0.1 – 0.15s` |
| 陰影階層變化 | `0.15 – 0.2s` |
| scrim 淡入 | `0.15 – 0.2s`（比內容先落地） |
| 同時進行的位移 | `0.2 – 0.35s` |

如果亮度跑得跟位移一樣慢，讀起來就會像*顏色在追著物件跑*。
**讓亮度先到，位置後到。**

## 6. 效能：哪些亮度屬性真的可以動畫

這個階層在哪裡都一樣，即使屬性名稱不同：

| 變化種類 | 成本 | 建議 |
|---|---|---|
| 既有圖層的不透明度 | ✅ 合成 | 永遠安全 |
| 圖層上的亮度／色調濾鏡 | ✅ 通常是合成 | 要做亮度動畫的首選 |
| 填色或背景色 | ⚠️ 重繪 | 小面積沒問題，全螢幕請實測 |
| 陰影，尤其是模糊的陰影 | ⚠️ 重繪，成本隨模糊半徑**和**面積上升 | 見下面的替代做法 |
| backdrop／背後圖層的模糊 | ❌ 昂貴 | 只用在小面積，或直接切換而不是做動畫 |
| 圓角、線寬 | ⚠️ 重繪，而且常常要重新三角化 | 改用裁切或預先算好的遮罩 |

**標準的替代做法，而且可以通用：** 永遠不要對昂貴的屬性做動畫。把**兩個**狀態都預先繪製成疊起來的圖層，交叉淡入淡出它們的不透明度。

以陰影來說，就是在元素後面放一張帶著*較高*階層的覆蓋層，平時停在不透明度 0，hover 時淡到 1。陰影本身完全不重繪，只有一個 alpha 值在變。在長清單上——幾十張卡片被連續掠過——差別非常明顯。

同一招也適用於圓角（兩張預先算好的遮罩）、色階（兩層填色）和模糊（兩份預先模糊過的副本）。它用記憶體換幀數。

## 7. 無障礙底線

亮度是一種表達手段，但它**不能是資訊的唯一載體**，而且有你不能跨過的數值下限。

- 內文對背景：**≥ 4.5:1**。大字（18.66px 粗體，或 24px）與互動元件的邊界：**≥ 3:1**。
- **絕對不要只用亮度傳達狀態。**「被選到的那個比較亮」對低視力或色覺差異的使用者根本不存在——一定要搭配形狀、圖示、邊框或文字。
- 焦點指示必須對周圍達到 **3:1**，而且**不能只靠亮度**。暗色主題最常見的失敗，就是一圈淺灰的 focus ring 在深色表面上整個消失。focus ring 要在兩種主題下分別驗證。
- 動畫過程中的中間狀態必須保持可讀。一段文字用 2:1 的對比淡入，對你的一部分觀眾來說，那整段時間就是空白的。**進場從不透明度 0 開始沒問題——要避免的是停在 `0.3` 這種「半可讀」的值當作靜止狀態。**
- **材質同樣受這些底線約束，而且更難量。** 剖面線沒有單一的背景值可以拿來量一個字符，所以誠實的讀法要取它最深的那條線，而不是平均值——這也是為什麼 §8 直接禁止它壓在連續文字底下，而不是給它一個要達到的比值。
- **在減少動態的設定下保留亮度變化。** 這正是亮度發揮價值的地方：當位移和縮放都被關掉，亮度和顏色仍然能傳達*狀態改變了*，而且不會引起暈眩。

## 8. 材質：只負責強化，永遠不是自己的一條通道

動態是時間。亮度是空間。材質——剖面線、顆粒、重複的紋路——兩者都不是：它是畫面上唯一**不會變**的東西。這就是它全部的工作。一個穩定的材質，是那些會動、會亮的東西得以被讀出來的*襯底*。

所以材質不是規格詞彙（`SKILL.md` §1）裡的第七個詞。它是 `lumin` 的修飾語，只有在強化亮度已經在說的那句話時才站得住腳，而且受兩條硬限制約束。

### 它屬於底，不屬於圖形

打剖面線的是圖版，永遠不是站在圖版上的那個東西。眼睛把材質讀成*材料*，所以替一個物件加材質，等於宣稱這個物件是由某種東西做的——而對一張卡片、一顆按鈕或一個對話框，你幾乎不會想說這句話。替它背後的底加材質，宣稱的是「底是一個表面，物件擱在上面」，而這正是 §1 用「光從上面來」已經在說的事。兩者說法一致，這份一致就是強化。

| 正當 | 不正當 |
|---|---|
| 一張圖片、一幅畫、一件標本背後的圖版 | 卡片、按鈕或面板本身 |
| 空狀態——*這塊圖版還沒畫上東西* | 任何承載連續文字的東西 |
| 標示為不可用或已保留的區域，**而且有標籤** | 只靠材質區分的狀態 |
| 每頁一塊重音區塊，用重音色 | 背後沒有任何論據的花紋 |

第三列是唯一真正的資訊用途，而且是借來的：在工程製圖裡，剖面線代表*剖面*或*不屬於這個視圖*，已經兩百年了。它在那裡行得通，是因為它永遠有標籤。只靠材質，和只靠亮度受同一條禁令管——§7。

### 它必須低於你用到的最小亮度階差

這就是那個數字，也是整套紀律：

> **剖面線的強度 < 兩個相鄰表面層級之間的差。**

如果剖面線比你的 `e2 → e3` 變化還強，層級就不再讀成高度，而開始讀成雜訊：眼睛面對同一個亮度差，被丟了兩種互相競爭的解釋。實務上這代表大約 **4–5% ink** 蓋在它所在的表面上，週期 **5–8px**——細到在閱讀距離上會化成一片稍暗的底，而不是一條條線。

兩個常被漏掉的推論：

- **暗色主題需要稍微多一點，不是少一點。** 對比敏感度在低亮度下會下降，所以同樣的 alpha 讀起來更淡。往上加大約一個百分點，不是三個——天花板仍然是表面層級的那一步，而在暗色主題裡，那一步正是承載層級的機制（§2）。剖面線蓋過它，就會像照搬過來的陰影一樣把畫面壓平。
- **一個產品只用一個角度、一個週期。** 兩個角度會被讀成兩種材料，而那是一句你並不打算對自己的物件說的話。挑 45°，然後就停在那裡。

### 文字永遠壓過它

在兩者可能競爭的兩個軸上，材質都讓位給文字：**堆疊順序和注意力。**

- **絕對不要把剖面線放在連續文字底下。** 不管 alpha 調得多低，也不管是不是「只有區塊的邊緣」。對比值是拿字符實際坐落的那個背景算出來的，而剖面線沒有一個背景——它有一個亮的和一個暗的，每幾個像素交替一次。拿平均值量出來的 4.5:1，在線條落下的地方就不是 4.5:1，而決定一個字母的筆畫活不活得下來的，正是那些線條。
- **替重音區塊留出空間，不要讓文字疊上去。** 如果版面沒有空間可以留，該被拿掉的是那個區塊——永遠不是文字周圍的呼吸空間。
- **在任何含有文字的區域裡，材質都不能是眼睛最先落上去的東西。** 如果它是，那就是太強了。把 alpha 調低到文字贏過它為止，或者把它拿掉。

這就是為什麼上面那張表裡正當的用途，都是承載*標籤*而不是文章的區域——而且就算是那樣，也要**在標籤後面把剖面線斷開**。工程製圖一直就是這麼做的：剖面線在註記的位置停住，因為註記才是必須被讀到的那一部分。一塊比文字大幾個像素的實心圖版，壓在剖面線上——整套技法就只有這樣。

這個檢查不需要工具：把眼睛放鬆失焦看著那塊區域，看什麼先浮出來。先浮出來的是什麼，你排在前面的就是什麼。如果先浮出來的是那些線條，那你就對一塊唯一工作只是被讀的區域，做了一個裝飾性的宣稱。

### 它不會動

**永遠不要對剖面線做動畫，也永遠不要對它底下的大面積表面做動畫。** 重複的花紋一旦動起來就會跟像素格子打拍，產生疊紋，而疊紋讀起來像算繪出錯，不像效果。

這是這份文件裡唯一沒有時序列的一節，而這正是重點：會變的是動態和亮度；材質是它們變化時的*襯底*。把那唯一一個固定參照拿掉，就是一個滿是精緻動畫的畫面最後失重的原因。

`recipes.md` §22 的骨架微光不是這條規則的例外。那是一條漸層帶掠過一塊平坦的佔位——不是有人在移動一個花紋。

**成本：** 重複漸層屬於重繪階（§6），而且是靜態的，所以只付一次。它變貴的那一刻，是它坐在一個因為別的原因就會重繪的圖層上——會捲動的容器，或正在交叉淡化的元素。把它留在小塊、不動的圖版上。

## 9. 檢查清單

只要做了任何牽涉到層級或狀態的東西，就跑一遍這份清單：

- [ ] 你在**暗色主題**下看過了嗎？層級還看得出來嗎？（通常看不出來——改用表面亮度。）
- [ ] 陰影是雙層（緊貼 ＋ 擴散）嗎？單層看起來像貼紙。
- [ ] 「更高」是用更大更柔表達的，而不是更黑嗎？
- [ ] 暗色主題的 rim light 有調弱，而不是直接沿用嗎？
- [ ] hover 和 press 有**同時改變位移和亮度**嗎？只做一半，表達力就少一半。
- [ ] 亮度變化比位移快嗎？
- [ ] 停用狀態是用專屬的顏色 token，而不是 50% 不透明度嗎？
- [ ] focus ring 在*兩種*主題下都達到 3:1 嗎？
- [ ] 有沒有哪個狀態**只**靠亮度區分？
- [ ] 在長清單裡，hover 陰影是交叉淡化的覆蓋層，而不是動畫化的陰影嗎？
- [ ] backdrop 模糊的面積有被限制住嗎？
- [ ] 剖面線在**兩種**主題下，都比最小的表面層級階差還安靜嗎？
- [ ] 它是打在底上而不是打在物件上，而且絕對沒有壓在連續文字底下嗎？
- [ ] 整個產品只用一個角度、一個週期嗎？
- [ ] 有沒有哪個東西只靠材質區分？
- [ ] 文字在每個地方都贏過材質嗎——沒有任何剖面線壓在連續文字底下，也沒有任何地方線條比文字先浮出來？
