# contrast.md — 明暗の表現力

モーションは**時間**の言語だ。そのものがどこから来て、どこへ行ったのか。
輝度は**空間**の言語だ。何が手前にあり、何が生きていて、いまどこを見るべきなのか。

どちらも単独では仕事の半分しかしない。**「持ち上がる」とは 8px 上へ動かすことではない。4px 上へ
＋ より大きく柔らかいシャドウ ＋ 明るいサーフェス——この 3 つが同時に起きて、ようやく脳は
*こちらに近づいてきた* と読む。** このファイルは、輝度をモーションに配線する話だ。

ここでの光学はプラットフォームに依存しない。具体的なプロパティに触れるのは §6 だけで、それも
どのレンダラーにもあるコスト階層の例としてでしかない。

---

## 1. メンタルモデル：光は上から来る

人間の視覚は光源が頭上にあると仮定する。輝度に関するあらゆる判断はそこに立脚しており、これを
破ると不気味か安っぽく見える。

| 表現したいこと | 輝度の配置 |
|---|---|
| **浮いている**（ボタン、カード、ポップオーバー） | 上辺のかすかな明るさ（リムライト）＋ 下のシャドウ |
| **沈んでいる**（入力欄、スロット、押下状態） | 上側のインナーシャドウ ＋ 下側のかすかな明るさ |
| **面一**（背景、区切り線） | シャドウは一切なし。サーフェス値の差だけ |
| **高く浮いている**（モーダル、ドラッグ中） | 広く、低い不透明度で、強くぼかしたシャドウ |

エレベーションが高いほど、シャドウは**より大きく、より柔らかく、より薄く**なる。より濃くではない。

初心者の誤りは「高い」を表そうとしてシャドウの黒を深くすることで、これは単に*汚い*と読まれる。
正しい操作は **blur** と **y オフセット**を増やし、アルファを**下げる**ことだ。

4 段階のはしごを offset / blur / alpha で示す。どんな形式で表現するにせよ、数値はこれだ：

| Tier | 意味 | 接触レイヤー | アンビエントレイヤー |
|---|---|---|---|
| **e1** | 面に置かれている | `0 1px 2px  / 8%` | — |
| **e2** | カード | `0 1px 2px  / 5%` | `0 2px 6px  / 7%` |
| **e3** | ポップオーバー、ドロップダウン | `0 2px 6px  / 5%` | `0 8px 20px / 6%` |
| **e4** | モーダル、ドラッグ中 | `0 4px 12px / 4%` | `0 20px 48px / 5%` |

肝は 2 層構造だ。ひとつは締まったレイヤー（**接触シャドウ**。そのオブジェクトに厚みがあると言う）、
もうひとつは広く拡散したレイヤー（**アンビエントオクルージョン**。どれだけ離れているかを言う）。
1 層だけのシャドウは、いつでもシールに見える。

**レンダラーにシャドウのプリミティブがないなら**——ゲームや 3D UI のランタイムの多くはそうだ——
同じ 2 層は、要素の背後に重ねた 2 枚のナインスライス画像で得られる。要素自身の矩形より数ピクセル
大きい小さく締まったもの 1 枚と、そこからかなり外へはみ出させた大きくぼけたもの 1 枚。動かすのは
その*アルファ*であって、サイズではない。このファイルの他の内容はそのまま当てはまる。

## 2. ダークテーマはエレベーションを別の機構で表現する——ここが間違われる

**暗いサーフェスの上ではシャドウは見えない。** ほぼ黒の上に落ちる黒いシャドウには、使える
コントラストがない。

ライトテーマのシャドウをそのままダークテーマへ移植すると、*すべての層が消え、画面がのっぺりする*。

ダークテーマは逆の機構を使う。**高いサーフェスほど明るい。**（物理的直感：光源に近い面ほど多くの
光を受ける。）

| レイヤー | ライトテーマ | ダークテーマ |
|---|---|---|
| 背景 | `#FFFFFF` | `#0E0E10` |
| サーフェス / カード | `#FFFFFF` + e2 | `#17171A`（約 5% 明るい） |
| ポップオーバー / ドロップダウン | `#FFFFFF` + e3 | `#1F1F23`（約 8% 明るい） |
| モーダル | `#FFFFFF` + e4 | `#26262B`（約 12% 明るい） |

**つまりテーマの切り替えはパレットの差し替えではなく、層を表現する機構そのものの差し替えだ。**
正しいトークンセットは、その 2 つを同時に変える。

| Token | Light | Dark |
|---|---|---|
| `surface` | `#FFFFFF` | `#0E0E10` |
| `elevated` | `#FFFFFF`（同じ——高さはシャドウが担う） | `#1F1F23`（**別の値**——高さはここが担う） |
| `shadow-e2` | `0 2px 6px / 7%` + `0 1px 2px / 5%` | `0 2px 8px / 50%` — オブジェクトを接地させはするが、もう層は担わない |
| `rim` | inset top `1px` white `60%` | inset top `1px` white `7%` — **はるかに弱く** |

忘れられがちなのが `rim` の行だ。ライトテーマ向けに調整した明るい上辺は、暗いサーフェスの上では
白く光るヘアラインになる。

ダークテーマの実務的な規則をもう 3 つ：

- **純黒を使わない。** OLED ではコンテンツと背景の境界がにじみ、純黒の上の白文字は高コントラストで
  きつい。`#0E–#14` あたりのほうが目に馴染む。
- **本文に純白を使わない。** `#E8E8EA` あたりまで落とすと、長文がずっと読みやすくなる。
- **彩度の高い色は彩度を落として明るくする。** ライトテーマ向けに調整したブランドカラーは、
  暗い背景の上ではたいてい蛍光色のように浮く。

## 3. コントラストの 3 つの仕事——混ぜてはいけない

| 仕事 | 手法 | これではない |
|---|---|---|
| **層**（何が手前か） | サーフェスの明るさ ＋ シャドウ | ボーダー（ボーダーが言うのは*仕切り*であって*高さ*ではない） |
| **フォーカス**（どこを見るか） | それ以外を暗くする（スクリム） | 対象を明るくする（すべてが明るくなって終わる軍拡競争） |
| **状態**（有効 / 無効 / 選択） | 明示的な色トークン | 不透明度だけ（下記参照） |

**フォーカスは周囲を暗くすることで働く。対象を明るくすることではない。** 1 つの画面が支えられる
明るいものの数には限りがあるので、明るくする方式はすぐ破綻する。暗くする方式は常に効く。
コントラストは相対的なものだからだ。

**無効状態を 50% の不透明度で表現しない。** 半透明の要素は背後にあるものを拾うので、背景が違えば
違って見えるし、テキストのコントラストを可読性の下限より下へ引きずり下ろす。専用の
`text-disabled` トークンを使うこと。

## 4. 輝度をモーションに配線する：複合表現

「表現を補強する」とは実際にはこういうことだ——単一のプロパティが運べる情報は少なすぎ、
**同じ方向へ動く複数プロパティの変化だけが、1 つの物理的イベントとして読まれる。**

以下はどれも、どのランタイムにも渡せる仕様として書いてある。

### 持ち上がる（カードのホバー）

| チャネル | From → To | タイミング |
|---|---|---|
| `y` | `0 → −4px` | `spring(0.2, 0)` |
| `scale` | `1 → 1.01` | `spring(0.2, 0)` |
| シャドウ | `e2 → e3`（より大きく柔らかく、**濃くではない**） | `dur 0.2  curve out` |
| サーフェス | `surface → surface-hover`（ライト：ほぼ変わらない／ダーク：**明るく**） | `dur 0.2  curve out` |

動きにはスプリングが要る。カーソルが離れることで割り込まれ得るからだ。輝度にはいらない——
そこは素のトゥイーンが正しく、この線で 2 つを分けるのが、たいていのランタイムでいちばん手数が
少ない。状態変化のための安価な宣言的レイヤー（CSS の `:hover`、スタイルシート、UI ステートマシン）
があるなら、輝度はそちらに置き、コードには動きだけを残す。

### 押す（沈む）

| チャネル | From → To | タイミング |
|---|---|---|
| `scale` | `1 → 0.97` | `spring(0.15, 0)` |
| シャドウ | `e2 → e1` に**加えて**、上側のインナーシャドウ `1–2px`、黒 `12%` | `dur 0.1  curve out` |
| 明度 | `1 → 0.96` | `dur 0.1  curve out` |

**縮む ＋ 暗くなる ＋ シャドウが締まる**が揃って *押し込まれた* という意味になる。縮むだけでは
*小さくなった*でしかなく、まったく別の主張だ。

### ドラッグ（つかまれた）

| チャネル | From → To | タイミング |
|---|---|---|
| `scale` | `1 → 1.04` | `spring(0.2, 0)` |
| シャドウ | `e2 → e4`、誇張して `0 24px 48px / 18%` | `dur 0.15  curve out` |
| 重なり順 | 兄弟要素より上へ | 即時 |

芝居がかったシャドウが正しい唯一の場所がドラッグだ。オブジェクトが目に見えて平面から離れないと、
ユーザーは自分がつかんでいるか確信できない。

### モーダルを開く（フォーカス）

暗転とコンテンツは同時に始まるが、**背景が先に着地する**：

| チャネル | From → To | タイミング |
|---|---|---|
| スクリムの opacity | `0 → 1` | `dur 0.2  curve out` ← 最初に終わる |
| ダイアログの opacity | `0 → 1` | `dur 0.2  curve out` |
| ダイアログの `scale` | `0.96 → 1` | `spring(0.28, 0.1)` |
| ダイアログの `y` | `+8px → 0` | `spring(0.28, 0.1)` |

退出は `feel.md` §5 の非対称性でこれを逆再生する：`dur 0.15`、`scale → 0.98`、`y → +4px`、
そしてスクリムは**最後に**去る。

スクリムの値：ライトテーマでは黒 `40–50%`。ダークテーマでは**別の設計**にしなければならない——
ほぼ黒の上に 50% の黒を重ねても何も起きないので、不透明度をずっと上げるか、ダイアログ自身を
明るくしてコントラストを稼ぐ。

背景ブラーはどこでも高くつく（下のレイヤー全体を再ペイントするか再サンプリングする）。狭い範囲なら
問題ないが、全画面では計測すること。低スペック端末にはフラットなスクリムを出荷する判断も考える。

## 5. 輝度は動きより速く変化する

輝度は**状態のシグナル**であり、変位は**プロセス**だ。状態は即座に確認されるべきで、プロセスは
時間をかけてよい。

| 変化 | 持続時間 |
|---|---|
| 明度 / 色の切り替え | `0.1 – 0.15s` |
| シャドウの段階変化 | `0.15 – 0.2s` |
| スクリムのフェードイン | `0.15 – 0.2s`（コンテンツより先に着地する） |
| 同時に走る動き | `0.2 – 0.35s` |

輝度が動きと同じ遅さで走ると、*色がオブジェクトを追いかけている*ように読まれる。
**明度を先に、位置を後に到着させること。**

## 6. パフォーマンス：どの輝度プロパティなら実際にアニメーションできるか

プロパティ名が違っても、階層はどこでも同じだ。

| 変化の種類 | コスト | 指針 |
|---|---|---|
| 既存レイヤーの opacity | ✅ コンポジット | 常に安全 |
| レイヤーへの明度／色調フィルタ | ✅ たいていコンポジット | 明度をアニメーションさせるときの第一候補 |
| 塗りつぶし色や背景色 | ⚠️ ペイント | 狭い範囲なら問題ない。全画面では計測する |
| シャドウ、特にぼかしたもの | ⚠️ ペイント。コストは blur 半径**と**面積に比例する | 下の回避策を参照 |
| 背景／背面レイヤーのブラー | ❌ 高コスト | 狭い範囲だけにするか、アニメーションではなく切り替える |
| 角丸、ストローク幅 | ⚠️ ペイント。しばしば再テッセレーションが走る | クリップか、あらかじめ描画したマスクを使う |

**定石の回避策、そしてこれは一般化する：** 高コストなプロパティは決してアニメーションさせない。
**両方**の状態を重ねたレイヤーとしてあらかじめ描画し、その opacity をクロスフェードする。

シャドウなら、要素の背後に*上の段階*を持つオーバーレイを置き、opacity 0 で待機させ、ホバーで 1 へ
フェードする。シャドウ自体は一度も再ペイントされず、変わるのはアルファ値 1 つだけだ。長いリスト
——何十枚ものカードを順にホバーする場面——では差は劇的になる。

**前提条件が 1 つあり、この手法がたいてい失敗する理由でもある：要素がクリップされていないこと。**
シャドウは自分のボックスの外側に描かれるので、`overflow: hidden` — 上部に画像を持つ角丸カードで
反射的に書くあれだ — があるとオーバーレイは丸ごと消える。しかも黙って消える。クロスフェード自体は
誰にも見えないレイヤーの上で走り続けるからだ。クリップするのはカードではなくメディアのほうに。
→ `errata.md` §A1

同じ手は角丸（あらかじめ描画した 2 枚のマスク）、色のグラデーション（2 枚の塗り）、ブラー
（あらかじめぼかした 2 枚のコピー）にも効く。メモリを払ってフレームを買う手だ。

## 7. アクセシビリティの下限

輝度は表現の手段だが、**情報の唯一の担い手にはなり得ない**し、越えてはならない数値上の限界がある。

- 本文と背景のコントラスト：**4.5:1 以上**。大きな文字（18.66px 太字、または 24px）と操作可能な
  コンポーネントの境界：**3:1 以上**。
- **状態を明度だけで示さない。** 「選択されているほうが明るい」は、ロービジョンや色覚特性の
  異なるユーザーには存在しない——常に形、アイコン、ボーダー、テキストと組み合わせること。
- フォーカスインジケータは周囲に対して **3:1** に達し、**明度だけに頼ってはならない**。ダークテーマ
  でよくある失敗は、淡いグレーのフォーカスリングが暗いサーフェスの上で完全に消えることだ。
  フォーカスリングは両方のテーマで個別に検証する。
- アニメーション途中の中間状態も読める状態を保つこと。コントラスト 2:1 でフェードインする文字は、
  観客の一部にとってはその時間ずっと空白だ。**出現を opacity 0 から始めるのは問題ない——避ける
  べきは `0.3` のような「半分読める」値に静止状態として居座らせることだ。**
- **reduced motion でも輝度の変化は残す。** ここは輝度が真価を発揮する場所だ。動きとスケールを
  切っても、明度と色は *状態が変わった* ことを伝え続け、しかもめまいを起こさない。

## 8. チェックリスト

層や状態を扱うものを作ったら、これを通すこと。

- [ ] **ダークテーマ**で見たか？ 層はまだ見えているか？（たいてい見えていない——サーフェスの明るさに切り替える。）
- [ ] シャドウは 2 層（締まった層＋拡散した層）になっているか？ 1 層だとシールに見える。
- [ ] 「高い」を、濃くではなく大きく柔らかく表現しているか？
- [ ] リムライトはダークテーマ向けに弱めてあるか？ そのまま持ち込んでいないか？
- [ ] ホバーと押下は**動きと輝度を同時に**変えているか？ 片方だけでは表現が半減する。
- [ ] 明度は変位より速く変化しているか？
- [ ] 無効状態は 50% の不透明度ではなく専用の色トークンか？
- [ ] フォーカスリングは*両方*のテーマで 3:1 に達しているか？
- [ ] 明度**だけ**で区別している状態はないか？
- [ ] 長いリストで、ホバーのシャドウはアニメーションではなくクロスフェードするオーバーレイになっているか？
- [ ] 背景ブラーの面積は限定されているか？
