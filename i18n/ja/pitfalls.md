# pitfalls.md — 症状 → 原因 → 対処

症状を引いて、該当の節を読む。原因は API ではなく*機構*でグループ化してあるので、ランタイムを
またいで通用する——退出アニメーションが落ちる原因は、Web フレームワークでもゲームエンジンでも
ネイティブツールキットでも同じ 3 つだ。

| 症状 | もっとも可能性の高い原因 |
|---|---|
| 退出アニメーションが発火しない | アニメーションする前に破棄されている → §1 |
| トリガーのたびに最初から再スタートする | アニメーション対象が作り直されている、または名目上の開始値から再ターゲットしている → §2 |
| 反転がガタつく、急停止する | 速度が引き継がれていない。Tier 2 の挙動 → §2 |
| リフローアニメーションが何も起きない | レイアウトが変わったことをシステムに伝えていない、または要素の種類が transform できない → §3 |
| コンテンツが伸びる、角丸が楕円になる | 矩形をスケールしているのに中身をカウンタースケールしていない → §3 |
| スクロール中にページ全体が震える | スクロールバーやセーフエリアの出現がリフローアニメーションを誘発している → §3 |
| フレーム落ち、カクつき | レイアウト段階またはペイント段階のプロパティをアニメーションさせている → §4 |
| スクロール連動の値が目に見えて段階的になる | 生のスクロール入力を平滑化していない → §5 |
| 読み込み時に画面が上から流れる | スクロール駆動のスプリングをゼロで初期化している → §5 |
| ドラッグの距離がポインタと合わない | transform やスケールのかかった祖先が座標空間を変えている → §6 |
| タッチデバイスでホバーが「貼りつく」 | 合成されたホバーイベント → §6 |
| アニメーションは終わったのに状態が変わらない | 発火しなかった完了コールバックにロジックをぶら下げている → §7 |
| ダークテーマでエレベーションが消える | 暗いサーフェスではシャドウが見えない → `contrast.md` §2 |
| アニメーション途中の文字が読めない | 中間状態のコントラストが低すぎる → `contrast.md` §7 |

---

## 1. 起きない退出

退出アニメーションは矛盾を抱えている。論理的にはもう存在しないものをアニメーションさせるのだから。
どのランタイムにも、その間だけ生かしておく機構が必要で、**失敗は必ず次の 3 つのどれかだ**。

1. **生かしておく仕組みが、削除される側の内部にある。** 破棄を遅らせる役目のラッパー自身が同じ
   条件で破棄されるなら、アニメーションするものが何も残らない。生かしておく仕組みは条件式の
   **外側**に置き、条件はその内側に置くこと。
2. **同一性が不安定。** システムは何らかのキーで「どれがどれか」を追跡する。そのキーが位置の
   インデックスなら、項目 2 を削除したとき項目 3 が項目 2 に*なる*ので、システムは削除ではなく
   更新として見る。安定した一意の id を使うこと。
3. **退出するものが、生かしておく仕組みの直接の子ではない。** 間に無関係なラッパーが 1 つ挟まる
   だけで機構はそれを見つけられない。ソースの木ではなく、実際の木を確認すること。

**入れ子の退出**はそれ自体が罠だ。サブツリー全体が一度に削除されると、子はたいてい自分の退出を
再生**できない**——親が先に終わり、子を道連れにする。子を先に去らせたいなら、明示的に順序づける
こと（`feel.md` §6：中身が去り、*それから*コンテナが閉じる）。

**設計上のテスト：** 退出のあいだ要素を生かしておく機構を名指しできないなら、あなたはまだ退出
アニメーションを持っていない。設計する前にアダプタでそれを見つけること。

## 2. 再スタート、再生成、失われた速度

**アニメーション対象が作り直されている。** レンダー／更新関数の内部で構築されたものは、毎フレーム
または毎更新ごとに新しいオブジェクトであり、前のオブジェクトのアニメーション状態を何も引き継がない。
構築を外へ持ち上げること。「最初の 1 回は動いて、その後は二度と動かない」の原因はこれが圧倒的に
多く、どの宣言的 UI システムでも同じ形で現れる。

**名目上の開始値から再ターゲットしている。** 飛行中に再トリガーされたアニメーションは、宣言上の
開始値ではなく**現在**値から始めなければならない。まず現在値を読むこと。要素が A と B のあいだの
どこかにいるときに「A から B へアニメーション」と言うものは A へ引き戻り、そのスナップは
ユーザーが操作したまさにその瞬間に起きる。

**速度が引き継がれていない。** これは Tier 2 の挙動（`SKILL.md` §2）であり、バグではなく機能の
欠如だ。抜け道は 3 つ、優先順に：

- 実際にジェスチャー駆動であるインタラクションについてはスプリングを自前で積分する——`spring.md` §3。
- `b ≤ 0.15` に保ち、速度ゼロからの再スタートが継続と見分けられないようにする。
- 再トリガーされ得るアニメーションは `dur ≤ 0.2s` に保つ。再スタートが気づかれる閾値より下だ。

**パラメータ体系を混ぜない。** ランタイムが持続時間と stiffness の両方を受け取るなら、片方を
設定するともう片方はたいてい——しかも黙って——無効になる。語彙を 1 つ選び（`Dv`/`b` を使い、
境界で変換する）、もう片方は決して設定しないこと。

## 3. リフローと共有要素のアニメーション

**何も起きない場合：**

- **その種類の要素は transform できない。** インラインのテキストボックス、一部のレイアウト管理下の
  コンテナ、多くの 2D UI ノードは transform を完全に無視する。transform できる要素に変えること。
- **レイアウトが変わったことがシステムに伝わっていない。** リフローアニメーションは*変化前*と
  *変化後*の計測を比較して動くので、その比較を何かがトリガーしなければならない。システムの更新
  サイクルを迂回する変更は比較を生まず、したがってアニメーションも生まない。
- **互いのレイアウトに影響する 2 つの要素が別々に更新されている。** 同じパスで計測される必要が
  ある。さもないと片方が、もう片方がまだ空けていない位置へアニメーションしてしまう。

**レイアウトはアニメーションシステムではなくレイアウトで駆動する。** アニメーションでサイズを
設定し、*かつ*同じサイズをリフローシステムにアニメーションさせるのは、1 つの数値を 2 つの
システムが奪い合っている状態だ。レイアウト変化は即座に起こさせ、その視覚的な差分をリフロー機構に
アニメーションさせること。

**コンテンツが伸びる（スケールによる歪み）。** スケールでアニメーションする矩形は、中身すべてを
歪ませる。文字は伸び、角丸は楕円になり、ボーダーの太さが変わる。対処、優先順に：

- 直接の子を逆比率でカウンタースケールする。
- アスペクト比が変わる要素（画像、テキストブロック）は**位置だけ**をアニメーションさせ、サイズは
  即座に変える。
- **角丸とシャドウは、補正するためにアニメーションシステムから見える値でなければならない。**
  スタイルシートや静的アセットに埋まった半径はカウンタースケールできない。
- ボーダーは完全には補正できない——1 ピクセルの下限がある。代わりにパディングを持つ親を
  ボーダーとして使う。

**スクロールコンテナや固定位置レイヤーの内側では**、コンテナのことをシステムに伝えないかぎり、
前後の計測が別の座標空間で取られる。どちらの場合もたいてい明示的なオプトインが要る。

**スクロール中のページの震え**は、ほぼ必ずスクロールバーやセーフエリアのインセットが出たり
消えたりしていることが原因で、それがコンテンツ幅を変え、すべてにリフローアニメーションを
誘発している。溝を恒久的に確保しておくこと。

**座標についての注記：** **親相対**の位置を計算するリフロー機構なら、遅れて動く子は動いている親に
くっついたままになる。**ページ絶対**の位置を計算するものは子を置き去りにする。子のトランジションが
親から浮いて見えるなら、理由はこれだ。

## 4. パフォーマンス

**常に安全**：transform（translate / scale / rotate）、opacity
**ペイント段階——計測せよ**：シャドウ、角丸、背景色、フィルタ
**レイアウト段階——避けよ**：width、height、top、left、margin、padding、ボーダー幅

普遍的な置き換え：**高コストなプロパティをアニメーションさせず、あらかじめ描画した 2 つの状態を
クロスフェードする。** ぼかしたシャドウは opacity をアニメーションさせる重ねたオーバーレイになり、
角丸は 2 枚のマスクになり、背景ブラーはあらかじめぼかした 2 枚のコピーになる。メモリを払って
フレームを買う手だ——`contrast.md` §6。

クリップやマスクが使えるなら、たいていそれが置き換えるプロパティより安い。角丸の矩形にクリップする
ほうが半径をアニメーションさせるより速く、リビールをクリップするほうが height をアニメーション
させるより速い。

**レイヤーのヒントは控えめに。** 「これを独立レイヤーへ昇格させる」ヒントはどれも GPU メモリを
消費し、それだらけのページはヒントのないページより遅い。計測した要素にだけ付けること。

**高くつくのはテキストだ。** テキストを断片に分割するとオブジェクト数が*一度だけ*増える。これは
構わない。毎フレームテキスト内容を書き換えると**継続的な**文字組みが走る。これは構う。最終的な
サイズを先に確保し、スクランブル効果には字送りが固定のフォントを使ってボックスが測り直されない
ようにすること。**1 文字ごとのブラーは特有の罠だ**——小さなレイヤーが多数でき、それぞれが blur
半径ぶん膨らんで大きく重なり合い、ブロック全体に 1 回ブラーをかけるよりはるかに高くつく。

## 5. スクロール

- スクロール入力は離散的だ。transform に直結すると段階的になる。必ずスプリングで平滑化すること
  ——`feel.md` §7。
- **そのスプリングを現在のスクロール値で初期化する。** さもないと読み込み時に画面が上から流れる。
  これは開発中——すでにページ最上部にいる——では再現しないので、常に本番へ流れていく。
- 固定はプラットフォームのネイティブな sticky 機構で行い、スクロールハンドラから位置を書き込まない。
  ハンドラ駆動の固定はコンポジタより 1 フレーム遅れ、目に見えて揺れる。
- スクロールトリガーのアニメーションには、明示的な**一度だけ発火**フラグと明示的な**閾値**
  （約 30% 可視）が要る。どちらも既定値はたいてい間違っている。
- 「進捗」が何を指すのかを厳密にすること。多くのスクロール API は範囲を 2 組の位置——対象上の点と
  コンテナ上の点——で表現しており、この組み合わせを逆にすると、要素が画面に入る前に終わっている
  アニメーションか、決して完了しないアニメーションになる。

## 6. ジェスチャーと座標空間

**ドラッグがポインタに追従しない** → 祖先に transform かスケールがかかっており、ポインタ座標と
要素座標が別の空間にある。ポインタのデルタを累積スケールで割るか、ポインタ位置を要素のローカル
空間へ変換してから使うこと。同じ原因はスケールされた親の内側のリフローアニメーションも壊す。

**タッチデバイスでホバーが「貼りつく」** → タッチ入力は、対応する終了イベントを持たないホバー
イベントを合成する。プラットフォームにフィルタ済みのホバーシグナルがあればそれを使う。なければ
タッチ終了時に自分でホバー状態をクリアし、ホバー効果を「実ポインタを持つデバイスか」の
クエリでゲートすること。

**タッチでドラッグがスクロールと競合する** → ジェスチャーが始まる前に、どちらの軸を自分が担うかを
プラットフォームに伝える必要がある。先に宣言すること。最初の move イベントの後で決めるのは常に
手遅れだ。スクロールはもう始まっている。

**子のタップが親のジェスチャーに飲み込まれる** → ジェスチャーシステムは入力パスの最後まで処理を
遅らせるのが一般的で、つまりジェスチャーのコールバック内で伝播を止めるのでは遅すぎる。生の
ポインタダウンで止めるか、システムが用意している明示的な「このジェスチャーを伝播させない」
オプションを使うこと。

**ドラッグの終わりにタップが発火する** → ポインタが約 3px を超えて動いた時点でタップをキャンセル
する。たいていのシステムが代わりにやってくれるが、検証すること。失敗の中身は、ユーザーがカードを
ドラッグして誤って開いてしまうことだ。

**画像をドラッグするとゴーストが出る** → プラットフォーム自身のドラッグ＆ドロップが自作のものと
競合している。その要素で無効化すること。

## 7. 状態、コールバック、ライフサイクル

**アニメーション完了コールバックに本当のロジックを載せてはいけない。** アニメーションが割り込まれた
とき、キャンセルされたとき、reduced motion でスキップされたときには発火しない——そしてその 3 つは
どれも普通の状況だ。状態はアニメーションを引き起こしたイベントから駆動し、アニメーションは表現に
とどめること。目安：**プロダクトからアニメーションをすべて削除しても、ロジックはすべて動くはずだ。**

**アニメーションと状態は食い違い得る。** 「メニューが開いているか」の真実の源がアニメーションなら、
割り込まれたアニメーションは、モデルに存在しない状態を残す。boolean を持ち、それに向かって
アニメーションさせること。

**毎更新ごとの新規オブジェクトに注意。** 更新のたびに新しく構築した設定オブジェクトを渡すと等値
判定が失敗し、アニメーションが延々と再生されるか、無意味な比較コストを払うことになる。外へ
持ち上げるか、メモ化するか、トークンとして名前を付けること。

## 8. 出荷前チェックリスト

- [ ] reduced motion はグローバルに扱われているか？ パララックスと自動再生はその上で個別に分岐しているか？
- [ ] スクロールトリガーのアニメーションは、妥当な閾値で一度だけ発火するか？
- [ ] transform であるべきところでレイアウト段階のプロパティをアニメーションさせていないか？
- [ ] 退出は実際に再生されるか——安定した id で、条件は生かしておく仕組みの内側にあるか？
- [ ] 退出は出現の 0.5–0.7× の長さで、より短い距離か？
- [ ] stagger の算数はしたか（間隔 × 個数 ≤ 0.5s）？
- [ ] プロダクト全体で使われているバウンス値はちょうど 1 つか？
- [ ] **ダークテーマで見たか？** エレベーションはまだ見えるか？ フォーカスリングは？
- [ ] すべてのアニメーションを 5 回続けて素早く再トリガーし、割り込みの挙動を見たか？
- [ ] 低スペック端末で、あるいは CPU を 4 倍スロットルして一度は動かしたか？
- [ ] 分割したテキストは、断片を隠したうえで適切なアクセシブルラベルを持っているか？
- [ ] 輝度だけ、あるいはアニメーションだけで伝えている状態はないか？
