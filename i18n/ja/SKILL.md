# Dynamization（日本語）

> これは `SKILL.md` の日本語版です。英語の正典はリポジトリ直下の `SKILL.md` にあります。
> API リファレンス（react / javascript / vue / doc-index）は英語のみで、`references/` にあります。

> モーションは**時間**の言語です。それがどこから来て、どこへ行き、今触れられるのかを伝えます。
> 明暗は**空間**の言語です。何が上にあり、何が生きていて、今どこを見るべきかを伝えます。
>
> 片方だけでは仕事の半分にしかなりません。「浮き上がる」とは要素を 4px 上へ動かすことではなく、
> **移動 ＋ 影が大きく柔らかくなる ＋ 表面が明るくなる、が同時に起きること**です。
> そうして初めて脳は「こちらに近づいた」と読み取ります。
>
> 「硬い」「のっぺりしている」と感じるインターフェースの原因は、まず曲線の美しさではありません。
> 物理的直感に反しているか、3 つ変えるべきところを 1 つしか変えていないかのどちらかです。

## 一、まずランタイムを選ぶ

| 状況 | 使うもの | インポート |
|---|---|---|
| React / Next.js | Motion for React | `npm i motion` → `import { motion } from "motion/react"` |
| React Server Component | 同上、パスのみ変更 | `import * as motion from "motion/react-client"` |
| Vue / Nuxt | Motion for Vue | `npm i motion-v` → `import { motion } from "motion-v"` |
| 素の JS / Webflow / Astro | vanilla | `npm i motion` → `import { animate } from "motion"` |
| hover で色が変わるだけ | **素の CSS**。ライブラリは不要 | — |
| ライブラリ無しでスプリング曲線が欲しい | CSS `linear()` を生成 | `i18n/ja/recipes.md` §CSS スプリング |

**そもそもライブラリが必要かを先に問うこと。** 単一要素・単一状態・中断される必要がないなら、
CSS の `transition` で十分です。Motion の価値は中断可能性、速度の引き継ぎ、レイアウトアニメーション、
ジェスチャー、オーケストレーション、スクロール連動にあります。どれも使わないなら 18kb を配る理由はありません。

## 二、5 つの黄金律

アニメーションを書く前にこの 5 つを通してください。1 つでも破ると、**なぜかは言えないが変**という結果になります。

### 1. 位置と大きさはスプリング、不透明度と色はトゥイーン

これは好みではなく、Motion 自身のデフォルトのロジックです（`motion-dom` のソースで確認済み）。

| 何が動くか | Motion が選ぶもの |
|---|---|
| `x` `y` `rotate` `skew` などの transform | spring、`stiffness: 500, damping: 25`（わずかにオーバーシュート） |
| `scale` 系 | spring、`stiffness: 550, damping: 30`（臨界減衰、**オーバーシュートしない**） |
| `opacity` `color` `filter` その他すべて | tween、`ease: [0.25, 0.1, 0.35, 1]`, `duration: 0.3` |
| キーフレーム 3 つ以上 | tween、`duration: 0.8` |

理由：空間を占めるもの（位置・大きさ）を脳は**実体**として扱い、実体には質量と慣性があります。
不透明度と色は実体ではなく「見えるかどうか」でしかないので、そこにスプリングを入れると点滅に見えます。

**帰結：`scale` にバウンスをつけてはいけません。** 弾む拡大はガラスにぶつかったように見えます。
Motion が scale を臨界減衰にしているのはそのためです。

### 2. アニメーションは中断可能で、速度を引き継がなければならない

最も重要で、最も見落とされる一条です。人が途中で気を変えるのは普通のことです。

- スプリングを使う：Motion は現在の速度を自動的に引き継ぐので、反転しても急停止しません。
  **これがスプリングがトゥイーンに勝る本当の理由であって、「弾むこと」ではありません。**
- キーフレームでは先頭に `null` を書く：`animate={{ x: [null, 100, 0] }}` ——
  始点へ跳ね戻らず、**現在値**から続きます。
- `setTimeout` でアニメーションを繋がないこと。シーケンス（`animate([...])`）か
  variants の `when` / `delayChildren` を使えば、まとめてキャンセルできます。
- View Transitions API は中断できません（中断すると終端へ飛びます）。中断が必要なら Motion の `layout` を使います。

### 3. 登場と退場は非対称

去っていくものを人に待たせてはいけません。

```jsx
// 登場：ゆっくりめ、easeOut（速く入って止まる）
initial={{ opacity: 0, y: 8 }}
animate={{ opacity: 1, y: 0, transition: { duration: 0.25, ease: "easeOut" } }}
// 退場：速く、easeIn（加速して去る）
exit={{ opacity: 0, y: 4, transition: { duration: 0.15, ease: "easeIn" } }}
```

退場は登場の **0.5〜0.7 倍**の時間、**移動距離も短く**。去るものは全行程を進む必要がなく、
目は「去った」ことさえ分かればよいのです。

### 4. 時間の階層：用途ごとに時間の予算が違う

| 階層 | 長さ | 用途 | カーブ |
|---|---|---|---|
| 即時フィードバック | `0.1〜0.15s` | 押下の縮小、チェックボックス、フォーカスリング | `easeOut` かスプリング |
| マイクロインタラクション | `0.15〜0.25s` | hover、ツールチップ、ボタンの色 | `easeOut` |
| コンポーネント遷移 | `0.25〜0.4s` | ドロップダウン、モーダル、アコーディオン、layout | spring `visualDuration: 0.3` |
| ページ／叙述 | `0.4〜0.8s` | 画面遷移、大きなヒーロー、多段キーフレーム | spring または tween + stagger |
| `1s` 超 | ほぼ間違い | loading / ambient / スクロール連動のみ許容 | — |

hover のアニメーションは **0.2s を超えてはいけません**。カーソルはもう離れているかもしれません。
距離が長ければ少し長くしてよいですが、**比例はしません**。距離 2 倍で時間は 20〜30% 増程度です。

> 完全な判断基準、スプリング引数の人間的な意味、リズムの設計、アンチパターン一覧 → `i18n/ja/feel.md`

### 5. 1 つの出来事では複数のプロパティを同じ向きに変える

単一プロパティの変化は情報量が足りません。**同じ向きの複数プロパティの変化こそが、
1 つの物理的な出来事として読み取られます。**

| 表したいこと | 最低限これだけ動かす |
|---|---|
| 浮上・接近（カード hover） | `y` が上へ ＋ 影が大きく柔らかく ＋ 表面が明るく |
| 押下・陥没 | `scale` が縮む ＋ 影が締まる ＋ 内側の影 ＋ 暗くなる |
| 持ち上げ（ドラッグ中） | `scale` 拡大 ＋ 広い影 ＋ z を上げる |
| 集中（モーダル起動） | 内容が登場 ＋ **背景を暗く**（スクリムが先に到達する） |
| 無効 | 専用の低コントラスト色トークン（**`opacity: 0.5` ではない**） |

明るさは*状態の信号*、移動は*過程*です。したがって
**明るさの変化は移動より速く**（およそ `0.12〜0.15s` 対 `0.2〜0.35s`）。

ダークテーマでは影がほぼ見えないため、高さは*表面を明るくする*ことで表します。
テーマの切り替えは配色ではなく、**表現の仕組みそのものの入れ替え**です。

> → `i18n/ja/contrast.md`

## 四、アクセシビリティは任意ではない

**大きな要素を移動または拡縮する**アニメーションはすべて reduced motion を扱う必要があります。
サイト全体なら 1 行です。

```jsx
import { MotionConfig } from "motion/react"
<MotionConfig reducedMotion="user">{children}</MotionConfig>
```

`reducedMotion="user"` は transform と layout のアニメーションを自動的に止め、
opacity と色は**残します**。これは iOS と同じ考え方で、「画面が変わった」ことは伝えつつ、
スライドではなくクロスフェードにするということです。

細かい制御には `useReducedMotion()`（Vue も同名）。
パララックス、動画の自動再生、無限ループは常に明示的な分岐が必要です。

## 五、パフォーマンスのレッドライン

すべてのブラウザでコンポジタに乗るのは `transform` と `opacity` だけです。これらは常に安全です。

- ❌ `width` / `height` / `top` / `left` / `margin` / `border-width` はレイアウトを誘発し、必ずコマ落ちします
- ⚠️ `box-shadow` / `border-radius` / `background-color` はペイントを誘発。小さい要素なら可、広い面積は実測を
- ✅ 影のアニメーションは `filter: drop-shadow(...)`、角丸は `clip-path: inset(0 round Npx)` へ
- ✅ サイズや位置を動かすなら `layout` prop を使うこと。Motion は内部で transform に置き換えます。ライブラリが存在する主な理由の 1 つです
- ⚠️ Motion の独立 transform（`x`, `scale`）は CSS 変数で実装されており、**ハードウェアアクセラレーションされません**。
  問題になる場面では `transform: "translateX(100px) scale(2)"` と書きます

## 六、公式の最新原文を取得する

ドキュメントサイトはコンテントネゴシエーションに対応しているので、権威ある原文は常に 1 コマンドで手に入ります
（このパックより新しいはずです）。

```bash
curl -sL -H "Accept: text/markdown" https://motion.dev/docs/<slug>
# 例：https://motion.dev/docs/react-transitions
```

または `scripts/fetch-doc.sh react-transitions`。全 slug は `references/doc-index.md` にあります。

**このパックと公式が食い違う場合は公式が正**です。ただし既知の例外が 1 つあります。
公式ページはスプリングの `stiffness` の既定値を `1` と書いていますが、**これは誤り**です。
ソースは `100` です。公式どおりに書くと、ほとんど動かないスプリングになります。
