差異 02

彈簧不再是 import 進來的，是算出來的

新增
references/spring.md
242 行

彈簧本來就是大家裝動畫函式庫的主要理由。新版把它整個攤開： spring(Dv, b) 到 k／c 的換算、一個 semi-implicit Euler 積分器、 三種阻尼狀態各自的解析解，以及怎麼把彈簧烘成 easing 表。

兩個參數都是人講得出口的：Dv 是「看起來花多久」， 排除掉收尾的餘震；b 是「過衝多少」。 換算式只有兩行：ζ = 1 − b、ω₀ = 2π / Dv，然後 k = ω₀²、c = 2ζω₀。

差異 03

新增了「執行環境能力分級」這個概念

SKILL.md §2
每份 adapter
開頭就宣告

舊版沒有這個，因為它只服務一個執行環境。新版要跨平台，就得先回答一個問題： 動畫跑到一半改變目標，會發生什麼事？ 這決定的是你「能設計什麼」，不只是「怎麼寫」。

分級中斷時的行為對設計的限制典型
Tier 1 帶著速度繼續走 整包規格照寫即可 SwiftUI · Compose · 手寫積分器
Tier 2 從當前值零速重啟 b ≤ 0.15，反向要縮短 CSS transition · WAAPI · TweenService
Tier 3 跳回起點或直接跳到終點 可重複觸發的一律 dur ≤ 0.2s @keyframes · View Transitions

有個反直覺的結論寫進去了：CSS transition 其實是 Tier 2，不是大家以為的 Tier 3—— 它會從當前計算值重新導向，只是速度歸零。而 View Transitions 這種「事前事後各拍一張」的機制， 在一個能力很強的環境裡反而是 Tier 3。

沒變的

核心論點一個字都沒改

SKILL.md
feel · contrast
recipes · pitfalls

兩個版本共同的主張：動態是時間的語言，亮度是空間的語言， 分開用各自只做了一半的工作。所謂「浮起」不是把東西往上移 4px， 而是位移＋更大更柔的陰影＋更亮的表面三件事同時發生。滑過看看差別：

只動位移

它只是往上移了一點。你會覺得有反應，但說不出它變成了什麼。

位移 ＋ 陰影 ＋ 表面

三件事同方向一起動，大腦才會把它讀成「這東西朝我靠近了」。

  • 進場與出場不對稱：出場跑進場的 0.5–0.7 倍，距離砍半。沒有人該為了一個正要離開的東西等待。
  • 亮度變化要比位移快（0.12–0.15s 對 0.2–0.35s），否則讀起來是顏色在追著物件跑。
  • 暗色主題的層次不是靠陰影，是靠表面更亮——換主題換的是機制，不只是色票。
  • scale 永遠不彈跳。會彈的放大讀起來像撞到玻璃。
